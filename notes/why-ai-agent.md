여기서 AI 에이전트는 목표를 수행하는 동안 모델이 다음 행동과 도구 사용을 선택하는 구조를 뜻합니다. AI 코딩 도구로 프로그램을 만드는 방식과 구분해, 서비스 안에서 에이전트를 사용할 이유를 다룹니다.

## 다음 행동을 미리 정할 수 있는가?

Anthropic은 코드로 정한 경로에 따라 실행하는 워크플로와, 모델이 진행 과정과 도구 사용을 동적으로 결정하는 에이전트를 구분합니다. 복잡성을 늘릴 때는 성능 개선과 함께 응답 시간·비용을 고려해야 한다고 설명합니다. [Building effective agents](https://www.anthropic.com/research/building-effective-agents)

이 구분을 기획에 적용하면 다음과 같이 비교할 수 있습니다.

| 방식 | 검토할 상황 | 예시 |
|---|---|---|
| 정해진 자동화 | 입력과 처리 규칙, 작업 순서를 정할 수 있음 | 조건 검사 후 알림 전송 |
| 언어모델 호출 | 문장 해석이나 생성이 필요하며 작업 범위가 정해져 있음 | 문의에서 요청 항목 추출 |
| AI 워크플로 | 여러 단계를 코드로 연결할 수 있음 | 검색 → 요약 → 형식 검사 |
| AI 에이전트 | 중간 결과에 따라 다음 검색이나 도구를 선택해야 함 | 자료의 누락 여부를 보고 추가 조사 |

LLM을 여러 번 호출하거나 도구를 사용한다는 사실만으로 자율 에이전트가 필요한 것은 아닙니다. 동적으로 선택할 지점을 구체적으로 적어야 합니다.

## 기획 예시 — 자료 조사 범위에 따른 선택

다음은 설명을 위한 가정입니다.

매번 정해진 자료 세 개를 읽어 같은 항목의 보고서를 만든다면 고정된 워크플로를 비교안으로 둡니다. 반면 첫 검색에서 자료가 부족한 항목을 찾고, 그 결과에 따라 검색어와 출처를 다시 선택해야 한다면 에이전트 구조를 검토할 수 있습니다.

이때도 보고서 저장, 외부 전송 같은 동작은 조사 과정과 구분해 권한과 승인 조건을 정합니다.

## 자율성을 허용할 범위 정하기

| 설계 항목 | 기획에서 정할 내용 |
|---|---|
| 목표 | 무엇을 제출하면 작업이 완료되는가? |
| 선택 범위 | 검색어·출처·도구 중 무엇을 모델이 선택할 수 있는가? |
| 도구 권한 | 조회만 가능한가, 저장·수정·전송도 가능한가? |
| 실행 한도 | 최대 실행 시간, 호출 수, 비용을 어떻게 제한하는가? |
| 중단 조건 | 자료 부족, 반복 실패, 권한 부족 시 어떻게 종료하는가? |
| 사용자 확인 | 어떤 실행 전에 내용과 영향을 보여 주고 승인받는가? |
| 실행 기록 | 어떤 자료와 도구를 사용했는지 어떻게 확인하는가? |

## 자율성의 효과를 검증하기

같은 조사 과제를 고정 워크플로와 에이전트로 수행하는 비교안을 세웁니다. 완료율과 근거 품질뿐 아니라 추가 호출 수, 완료 시간, 사람의 수정량도 함께 봅니다.

정상 입력 외에 ‘검색 결과 없음’, ‘도구 오류’, ‘서로 충돌하는 자료’를 포함해 중단과 재시도 동작도 확인합니다. 단계를 더 실행했는지보다 사용자가 요구한 결과를 얻었는지가 평가 기준이 됩니다.

## 기술 선택 이유를 기록하는 문장

> [작업]은 중간 결과에 따라 [다음 행동]이 달라져 에이전트를 검토한다. 모델의 선택 범위는 [도구·행동]으로 제한하고, [한도·중단·승인 조건]을 적용한다. 고정 워크플로 대비 [품질·시간·비용]으로 채택 여부를 판단한다.
