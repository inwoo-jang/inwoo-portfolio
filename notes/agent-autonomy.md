> 에이전트의 자율성이 무조건 높다고 좋은 건 아니다. 실행 권한, 결과 영향도, 복구 가능성 등을 고려해 자율성을 다르게 설계해야 한다. 이 정책은 백엔드의 실행 제어뿐 아니라 승인·거절·실행 내역 등 UI/UX에도 반영되어야 한다.

## 문제 제기

AI 에이전트는 사용자의 요청을 이해하고, 필요한 도구를 선택하며, 실제 행동까지 수행할 수 있다. 그렇다면 사람의 개입 없이 더 많은 작업을 완료하는 에이전트가 반드시 좋은 에이전트일까?

- 자율성이 높아지면 업무 효율이 개선될 수 있지만, 잘못된 판단이 실제 행동으로 이어질 위험도 커진다
- 모든 행동에 승인을 요구하면 자동화의 이점이 줄고 사용자의 검토 부담이 늘어난다

따라서 에이전트 기획에서는 **얼마나 많은 작업을 자동화할 것인가보다, 어떤 행동을 어떤 조건에서 자동화할 것인가**를 먼저 고민해야 한다.

## 리서치에서 발견한 점

### 실제 운영 환경에서는 자율성이 제한적으로 적용된다

*Measuring Agents in Production*은 실제 운영 중인 에이전트들이 짧고 통제 가능한 실행 흐름을 사용하는 경향을 보여준다. 모델의 기술적 능력과, 실제 서비스에서 허용되는 실행 권한은 구분해야 한다.

### 사용자의 숙련도에 따라 상호작용 방식이 달라진다

Anthropic의 *Measuring AI Agent Autonomy in Practice*에서는 숙련된 사용자가 자동 승인을 더 적극적으로 활용하면서도, 필요할 때 에이전트의 실행을 중단하는 행동이 관찰됐다. 다만 숙련도가 높다는 이유만으로 고위험 작업의 실행 권한까지 넓히는 것이 적절한지는 별도로 판단해야 한다.

### 사람의 승인 자체가 안전성을 보장하지는 않는다

반복적인 승인 요청은 검토 피로와 형식적인 승인으로 이어질 수 있다. Human-in-the-loop는 승인 버튼을 추가하는 것이 아니라, 사람이 충분한 정보를 바탕으로 실제 판단하고 개입할 수 있도록 설계하는 일이다.

## 자율성을 결정하는 기준

자율성은 다음 세 가지 기준으로 나눠 설계할 수 있다고 생각한다.

| 구분 | 주요 판단 기준 |
|---|---|
| 실행 권한 | 사용자 위임 범위, 조직 정책, 법적 제한 |
| 작업 위험 | 결과 영향도, 복구 가능성, 불확실성, 오류 확산 가능성 |
| 사용자 경험 | 숙련도, 업무 맥락, 승인 피로도 |

- 권한이 없는 행동은 실행하지 않는다
- 권한이 있는 행동이라도 위험 수준에 따라 자동 실행과 사전 승인을 나눈다
- 숙련도는 승인 방식과 정보 제공 수준을 조정하는 요소일 뿐, 필수 안전 정책을 우회하는 근거가 되어서는 안 된다

## 자율성 정책을 UX로 구현하기

자율성 정책은 백엔드의 실행 제어뿐 아니라 사용자 경험에도 반영되어야 한다.

| 정책 | 화면에서 제공할 것 |
|---|---|
| 자동 실행 | 위험이 낮고 허용된 작업은 자동 처리하되, 실행 내역을 확인할 수 있게 한다 |
| 조건부 승인 | 실행 전 변경 대상, 예상 결과, 승인이 필요한 이유를 제시한다 |
| 실행 금지 | 금지된 이유와 가능한 대안, 권한 요청 경로를 안내한다 |
| 실행 후 관리 | 작업 기록, 중단, 오류 대응과 복구 수단을 제공한다 |

중요한 것은 승인 절차가 있느냐가 아니라, **사용자가 에이전트의 행동을 이해하고 통제할 수 있느냐**이다.

## 자율성의 성과는 어떻게 평가할까?

자율성이 높다는 사실만으로 에이전트의 품질을 판단하기는 어렵다. 기존의 작업 성공률·안전성·운영 효율성 평가 개념을 참고해 다음 지표를 함께 볼 수 있다.

| 평가 영역 | 예시 지표 |
|---|---|
| 업무 성과 | 자율 작업 완료율 |
| 안전성 | 위험 행동 실행률, 정상 작업 오차단율 |
| 승인 효율 | 불필요한 승인 요청 비율, 사람의 검토 시간 |
| 운영 비용 | 오류 복구 시간과 비용 |
| 비즈니스 가치 | 자동화 편익에서 검토·운영·오류 비용을 뺀 순편익 |

이는 지표 구성안이다. 실제 서비스에 적용하려면 각 지표의 분모, 측정 범위, 위험 수준별 허용 기준을 구체화해야 한다.

## 현재의 생각

좋은 에이전트는 모든 일을 혼자 처리하는 에이전트가 아니라, **스스로 실행해도 되는 일과 사람의 판단이 필요한 일을 적절히 구분하는 에이전트**일 수 있다. 이를 위해 기획자는 모델 성능뿐 아니라 실행 권한, 위험 수준, 승인 경험, 오류 복구와 운영 지표를 함께 설계해야 한다.

다만 위험 기반 차등 승인이 전면 승인 방식보다 실제로 더 나은 업무 성과와 안전성을 제공하는지는 검증이 필요하다.

## 남은 질문

- AI의 정확도가 충분히 높아져도 사람의 승인이 필요한 작업은 무엇일까?
- 승인 요청을 줄이는 것과 실질적인 인간 통제를 강화하는 것은 양립할 수 있을까?
- 사용자의 숙련도와 서비스 운영 이력에 따라 자율성을 동적으로 조정할 수 있을까?
- 자율성 정책의 적절성을 어떤 실험과 KPI로 검증할 수 있을까?
