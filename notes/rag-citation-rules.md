RAG는 검색한 자료를 바탕으로 AI가 응답을 생성하는 방식입니다. 검색 결과가 없거나 응답의 인용이 잘못된 경우를 처리하기 위해 적용한 규칙을 정리했습니다.

## 근거 유무와 인용 오류에 따른 처리

| 검사 상황 | 처리 방식 |
|---|---|
| 참조할 근거 0건 | LLM을 부르지 않고 고정 문구 반환 ("검토한 자료에서 근거를 확인하지 못했다") |
| 목록에 없는 인용 ID | 코드로 삭제 |
| 인용 없는 문장 | 검증 단계로 넘기기 전에 제외 |
| 보고서 구성 | 요약은 LLM으로 생성하고, 나머지 장과 참고문헌은 코드로 조립 |
| 같은 논문의 사본이 여러 개 검색됨 | 중복을 제거해 출처 1개로 계산 |

## 검색된 근거가 없을 때의 처리

```python
def synthesis(state):
    context, allowed = _build_context(state)
    if not allowed:
        return {"synthesis": NO_EVIDENCE}      # LLM 호출 없음
    out = model.with_structured_output(SynthesisOut).invoke(messages)
    return {"synthesis": validate_synthesis(out, allowed)}   # 없는 ID 제거
```

## 인용 표기 형식 통일

```text
(ID) → [ID]
[A][B] → [A, B]
```

## 구현 중 확인한 문제와 해결

- 요약이 영어로 나오고 인용이 소괄호로 섞여 나왔다. 프롬프트에 작성 규칙을 넣고, 표기는 코드로 한 번 더 통일했다
- 근거 원문을 그대로 전달했을 때, LLM이 원문을 옮겨 써 검증을 통과하지 못했다. 해당 단계에는 원문 대신 근거 ID를 전달하고, 인용이 없는 문장을 제외하도록 수정했다
- 기술 정식 명칭으로 검색하면 결과가 0건이거나 무관한 자료가 늘었다. 이 실습에서는 짧은 이름으로 검색했을 때 관련 자료를 찾기 수월했다
- 근거 0건 처리를 넣어 두니 API 키 없이 실행하는 테스트에서도 모델 호출 없이 해당 노드가 완료됐다

## 적용할 때 확인할 점

- 근거가 없을 때 보여 줄 문구를 시스템 오류 메시지와 구분해 정한다
- 응답 생성 단계와 검증 단계에서 같은 인용 표기 형식을 사용한다
- 인용 ID가 유효한지 검사한 뒤, 출처의 내용이 해당 주장을 뒷받침하는지도 별도로 검증한다

## 핵심 요약

> 근거가 없을 때는 응답 생성을 건너뛰고, 인용 ID와 문장의 근거를 각각 검사합니다. 이 규칙은 근거 없는 응답의 위험을 줄이지만, 사실과 다른 응답을 완전히 방지하지는 못합니다.
