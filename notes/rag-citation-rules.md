RAG는 검색한 자료를 바탕으로 AI가 답을 만드는 방식이다. 캡스톤에서 **근거가 없을 때와 인용이 틀렸을 때 어떻게 할지** 규칙을 정했다.

## 겪은 문제

- 요약이 영어로 나오고, 인용 표기가 소괄호로 섞여 나왔다. 프롬프트에 작성 규칙을 넣고, 표기는 코드로 한 번 더 통일했다
- 근거 원문을 그대로 넘겼더니 LLM이 원문을 옮겨 써서 검증을 통과하지 못했다. 그 단계에는 원문 대신 근거 ID를 넘기고, 인용 없는 문장은 빼도록 고쳤다
- 기술 정식 명칭으로 검색하면 결과가 0건이거나 무관한 자료가 늘었다. 이 실습에서는 짧은 이름으로 검색할 때 관련 자료를 찾기 쉬웠다
- 근거 0건 처리를 넣고 나니, API 키 없이 돌리는 테스트에서도 해당 노드가 모델 호출 없이 끝났다

## 정한 규칙

| 상황 | 처리 |
|---|---|
| 참조할 근거 0건 | LLM을 부르지 않고 고정 문구 반환 ("검토한 자료에서 근거를 확인하지 못했다") |
| 목록에 없는 인용 ID | 코드로 삭제 |
| 인용 없는 문장 | 검증 단계로 넘기기 전에 제외 |
| 보고서 구성 | 요약만 LLM이 쓰고, 나머지 장과 참고문헌은 코드로 조립 |
| 같은 논문의 사본이 여러 개 검색됨 | 중복을 제거해 출처 1개로 계산 |

```python
def synthesis(state):
    context, allowed = _build_context(state)
    if not allowed:
        return {"synthesis": NO_EVIDENCE}      # LLM 호출 없음
    out = model.with_structured_output(SynthesisOut).invoke(messages)
    return {"synthesis": validate_synthesis(out, allowed)}   # 없는 ID 제거
```

인용 표기 통일:

```text
(ID) → [ID]
[A][B] → [A, B]
```

## 이 규칙이 막지 못하는 것

인용 ID가 목록에 있는지는 코드로 확인할 수 있다. 하지만 **그 출처가 정말 그 주장을 뒷받침하는지**는 이 규칙만으로 알 수 없다. 근거 없는 응답의 위험은 줄였지만, 틀린 응답을 완전히 막지는 못한다.
