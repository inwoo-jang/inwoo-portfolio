## 한 줄 비교

**이미지**는 애플리케이션과 실행 환경을 담은 *읽기 전용 틀*이고,
**컨테이너**는 그 이미지로 띄운 *실행 중인(또는 멈춘) 인스턴스*입니다.
클래스와 객체의 관계에 비유하곤 합니다.

| 구분 | 이미지 | 컨테이너 |
|---|---|---|
| 상태 | 읽기 전용, 변하지 않음 | 이미지 위에 쓰기 가능한 층이 추가됨 |
| 만드는 방법 | `docker build` (Dockerfile) | `docker run` (이미지로부터) |
| 목록 보기 | `docker images` | `docker ps -a` |
| 삭제 | `docker rmi` | `docker rm` |
| 개수 | 하나의 이미지로 | 여러 컨테이너를 띄울 수 있음 |

## 기억할 점

- 컨테이너 안에서 바꾼 파일은 컨테이너를 삭제하면 함께 사라집니다. 남겨야 하는 데이터는 **볼륨**에 둡니다.
- 이미지는 여러 층(layer)으로 쌓이고, 같은 층은 여러 이미지가 공유합니다.
- 컨테이너를 고쳐서 다시 쓰기보다, Dockerfile을 고쳐 이미지를 다시 빌드하는 편이 재현하기 쉽습니다.

## 기본 명령

```bash
docker build -t my-app:1.0 .        # 현재 폴더의 Dockerfile로 이미지 만들기
docker run -d -p 8080:8080 my-app:1.0   # 이미지로 컨테이너 실행
docker ps                           # 실행 중인 컨테이너
docker stop <컨테이너 ID>
docker rm <컨테이너 ID>
```
