AI 서비스 기획은 사용자가 해야 할 일을 살펴보고, 그중 AI로 개선할 수 있는 부분을 찾는 과정입니다. ‘답변을 생성할 수 있다’에서 더 나아가, 사용자가 결과를 확인하고 다음 행동을 마칠 수 있는 흐름까지 설계해야 합니다.

## 먼저 구분할 질문

AI 서비스, ML, 에이전트, sLLM은 서로 다른 단계의 선택입니다. 하나의 서비스에서 함께 사용할 수도 있습니다.

| 구분 | 기획에서 답할 질문 |
|---|---|
| AI 서비스 | 어떤 사용자 문제를 개선할 것인가? |
| 전통적인 ML | DL·LLM과 비교해 표 데이터의 분류·예측에 적합한가? |
| 언어모델 | 어떤 문장을 이해·추출·요약·생성해야 하는가? |
| AI 에이전트 | 실행 중 얻은 정보에 따라 다음 행동을 모델이 선택해야 하는가? |
| sLLM | 작은 언어모델로 필요한 품질과 운영 조건을 충족할 수 있는가? |

언어모델도 머신러닝으로 학습한 모델입니다. 에이전트는 모델의 크기와 별개로 작업을 실행하는 구조에 관한 선택입니다.

## 현재 사용자 흐름에서 개선할 부분 찾기

Google PAIR는 사용자 요구와 AI의 강점이 만나는 지점을 찾고, 규칙 기반 방식으로도 해결할 수 있는지 검토하도록 안내합니다. [People + AI Guidebook](https://pair.withgoogle.com/guidebook-v2/chapter/user-needs/)

이를 기획 검토에 적용하면 다음 질문으로 정리할 수 있습니다.

- 누가, 어떤 상황에서, 무엇을 완료하려 하는가?
- 현재 어느 단계에서 시간이 오래 걸리거나 누락이 생기는가?
- 화면 개선, 검색 필터, 계산식, 정해진 자동화로 해결할 수 있는가?
- AI 결과를 검토하고 수정하는 시간을 포함해도 이득이 있는가?
- 잘못된 결과가 나왔을 때 사용자가 발견하고 복구할 수 있는가?

## 기획 예시 — 문의 담당자 배정 보조

다음은 설명을 위한 가정입니다.

담당자가 문의를 읽고 유형을 분류한 뒤 담당 팀을 고르는 업무를 생각해 볼 수 있습니다. 문의에 적힌 단어가 늘 같다면 키워드 규칙을 먼저 비교합니다. 표현은 달라도 비슷한 의도를 찾아야 한다면 분류 모델이나 언어모델을 후보로 둡니다.

첫 범위는 ‘담당 팀 후보와 분류 이유 제시 → 담당자 확인·수정 → 배정’으로 정합니다. 자동 배정까지 할지는 이 보조 기능의 결과를 확인한 뒤 별도로 판단합니다.

| 설계 항목 | 검토할 내용 |
|---|---|
| 입력 | 문의 본문, 첨부 여부, 사용 가능한 업무 정보 |
| 출력 | 문의 유형, 담당 팀 후보, 판단에 사용한 문구 |
| 사용자 행동 | 후보 확인, 수정, 배정 확정 |
| 예외 | 정보 부족, 분류 불가, 시스템 오류를 각각 안내 |
| 대체 흐름 | AI를 사용할 수 없어도 수동 배정 가능 |

## 도입 효과를 확인할 방법

기존 방식과 AI 보조 방식을 같은 종류의 문의로 비교하는 검토안을 세웁니다. 합격 기준은 업무 담당자와 사전에 정하며, 아래 항목은 측정 설계의 예시입니다.

- 문의 접수부터 배정 확정까지 걸린 시간
- 담당자가 후보를 수정한 비율과 잘못 배정된 문의 수
- 검토·재작업에 든 시간과 운영 비용
- 분류하기 어려운 문의가 실제 담당자에게 전달된 비율

평균만 보면 예외 상황이 가려질 수 있으므로 짧은 문의, 복합 문의, 정보가 부족한 문의도 구분해 확인합니다.

## 도입 판단을 기록하는 문장

> [사용자]가 [상황]에서 [작업]을 완료하도록 [AI 기능]을 보조 수단으로 제공한다. 기존 [방식]과 비교해 [완료 시간·오류·비용]을 확인하고, [예외]는 [대체 흐름]으로 처리한다.
