AI 에이전트가 만든 보고서를 글자 수만으로 평가하자 내용이 부족한 결과도 통과했습니다. 형식은 코드로 검사하고, 의미는 LLM Judge(AI 모델을 이용한 평가)로 확인하도록 기준을 나눈 기록입니다.

## 검사 항목과 평가 역할

형식 검사, 의미 평가, 최종 통과 여부 계산을 구분했습니다.

| 검사 항목 | 평가 주체 | 예시 |
|---|---|---|
| 형식·개수·범위 | 코드 | 근거 3건 이상, 인용 번호 범위, 필수 항목 존재 |
| 내용과 근거의 일치 여부 | LLM Judge | 문장의 주장을 근거가 뒷받침하는지, 한계를 구체적으로 설명했는지 확인 |
| 통과 여부 | 코드 | Judge가 낸 문장별 판정으로 비율 계산 |

## 단계별 통과 기준

검색·분석·보고서 생성이 끝날 때마다 코드로 검사합니다. 아래 수치는 이 프로젝트에서 정한 기준입니다.

| 단계 | 통과 기준 | 실패하면 |
|---|---|---|
| 검색 | 근거 3건 이상, 출처·본문 빈칸 없음 | 실패 사유를 다음 검색어에 넣고 1회 재시도 |
| 분석 | 대상마다 결과 + 인용, 또는 "판단 불가 + 이유" | 실패한 대상만 1회 재분석 |
| 보고서 | 서로 다른 인용 3개 이상, 한계 서술 있음 | 사유를 넣고 1회 재작성 |

## 근거 일치 비율(Faithfulness)

보고서의 사실 주장 중 근거로 뒷받침되는 주장이 얼마나 되는지 계산했습니다.

```text
근거로 뒷받침된 사실 주장 수 ÷ 전체 사실 주장 수 ≥ 0.8
사실 주장 0개면 미통과
```

## LLM 평가 설정

- `temperature=0`, JSON schema strict로 한 번 호출
- 보고서를 코드가 문장 단위 id로 나눠서 넘김 (평가할 문장이 누락되거나 합쳐지는 것을 방지)
- 보고서·근거 안의 문구는 지시가 아니라 평가 데이터로 취급하라고 명시

## 구현 중 확인한 문제와 해결

- 글자 수 300자 기준만 있을 때 328자짜리 일반론 보고서가 통과했다
- 화면에는 세 기업이 모두 표시됐지만, 다음 단계에는 마지막 기업의 결과만 전달되고 있었다
- 평가 기준을 바꾸자 오류 없이 생성된 보고서도 평가 항목 5개 중 4개를 통과하지 못했다 (근거 일치 비율 23/30 = 0.767)
- 같은 보고서를 두 번 평가했을 때 통과 여부는 같았지만, 근거 일치 비율은 17/32와 17/30으로 달랐다. `temperature=0`으로 설정해도 평가 결과가 달라질 수 있었다
- 자료가 없는 대상은 "판단 불가"로 두는 게 맞았다. 보고서의 형식을 채우기 위해 내용을 만들면 사실과 다른 응답이 된다

## 적용할 때 확인할 점

- 기준을 만들면 일부러 기준을 어긴 입력을 넣어 실제로 걸러지는지 먼저 본다
- 측정값(시간, 개수)과 판정(정상/결함)을 따로 적는다
- 통과 기준에 가까운 결과는 두 번 평가해 판정의 변동을 확인한다
- `recursion_limit`은 재시도 횟수가 아니라 그래프 단계 상한이다. 재시도 상한은 따로 둔다

## 핵심 요약

> 형식·개수는 코드로 검사하고, 내용이 근거와 일치하는지는 LLM으로 평가합니다. 평가 결과의 최종 검토는 사람이 수행합니다.
