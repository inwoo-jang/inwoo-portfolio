이 글에서는 sLLM(Small Language Model)을 상대적으로 작은 언어모델이라는 의미로 사용합니다. 특정 파라미터 수를 공통 기준으로 두기보다, 맡길 작업과 실행 환경에서 필요한 품질을 충족하는지 확인하는 관점으로 정리합니다.

## 작은 모델이 필요한 이유를 구체화하기

Microsoft Research는 특정 업무 애플리케이션에서 작은 모델을 조정해 더 큰 모델과 정확도·실행 시간을 비교한 사례를 제시합니다. 이는 해당 과제의 결과이며, 다른 업무에서도 같은 성능을 보장하는 것은 아닙니다. [SLM application interactions case study](https://www.microsoft.com/en-us/research/publication/small-language-models-for-application-interactions-a-case-study/)

이런 사례를 도입 검토에 활용하려면 ‘작은 모델이면 충분하다’는 가설을 실제 업무 입력으로 확인해야 합니다.

| 도입 가설 | 확인할 조건 |
|---|---|
| 제한된 작업에 필요한 품질을 낼 수 있음 | 정해진 항목 추출·분류에서 누락과 오답 확인 |
| 응답 시간이나 자원 사용을 줄일 수 있음 | 같은 장비·입력 길이·동시 요청 조건에서 측정 |
| 조직이 정한 환경에 배포할 수 있음 | 모델 배포 권한, 장비, 외부 연결 경로 확인 |
| 반복 작업의 비용을 줄일 수 있음 | 추론뿐 아니라 장비·운영·검수 비용까지 비교 |

## 모델 크기와 별도로 결정할 것

- **작은 모델과 업무 특화 모델:** 크기가 작다고 업무 지식을 자동으로 갖는 것은 아니다. 프롬프트, 검색 자료, 추가 학습이 필요한지 따로 판단한다.
- **작은 모델과 자체 운영:** 작은 모델도 외부 서비스로 사용할 수 있다. 자체 운영은 배포 방식에 관한 선택이다.
- **자체 운영과 데이터 통제:** 모델을 내부에 배포해도 로그, 외부 검색, 연결 도구로 데이터가 전달되는 경로는 별도로 확인한다.
- **모델 크기와 양자화:** 양자화는 가중치를 낮은 정밀도로 저장해 메모리 요구량을 줄이는 방법이다. 모델의 파라미터 수를 줄이는 것과 구분한다. [Hugging Face 양자화 개요](https://huggingface.co/docs/transformers/quantization/overview)

## 기획 예시 — 요청 문장에서 항목 추출하기

다음은 설명을 위한 가정입니다.

짧은 요청 문장에서 ‘요청 종류·희망 일정·담당 팀’을 추출해 입력 폼을 채우는 기능이라면, 작은 모델을 후보로 비교할 수 있습니다. 문장에 없는 일정은 만들지 않고 빈값으로 돌려주도록 출력 규칙을 정합니다.

긴 문서를 종합하거나 복잡한 판단까지 맡기려면 그 작업도 평가에 포함해야 합니다. 짧은 추출 과제에서 얻은 결과를 다른 작업의 근거로 사용하지 않습니다.

## 같은 조건으로 비교할 항목

| 비교 항목 | 측정·확인 방법 |
|---|---|
| 업무 품질 | 필수 항목 누락, 잘못된 값, 없는 정보 생성 비율 |
| 예외 처리 | 오타, 여러 요청, 정보 부족, 긴 입력에서의 동작 |
| 응답 시간 | 평균과 함께 느린 요청의 지연 시간, 동시 요청 처리 확인 |
| 전체 비용 | 장비·호스팅·유지보수·추가 학습·검수 비용 포함 |
| 배포 조건 | 라이선스, 사용 가능한 장비, 버전 갱신과 장애 대응 |

요청당 추론 비용이 낮아도 검수와 재처리가 늘면 전체 비용은 커질 수 있습니다. ‘업무 기준을 통과한 결과 한 건을 얻는 데 드는 비용’도 비교안에 포함합니다.

## 품질이 부족할 때의 흐름 정하기

필수 항목 누락처럼 코드로 확인할 수 있는 실패는 재입력 요청이나 사람 검토로 연결할 수 있습니다. 더 큰 모델로 넘기는 방식도 후보지만, 외부 전송이 가능한 데이터와 비용 한도를 먼저 정합니다.

모델이 말하는 자신감만으로 정확성을 판단하지 않고, 별도의 평가 데이터와 검사 규칙으로 전환 기준을 확인합니다.

## 기술 선택 이유를 기록하는 문장

> [제한된 작업]에서 [평가 데이터]로 필요한 품질을 확인한다. [배포 조건]에서 응답 시간과 전체 운영 비용을 비교해 작은 모델의 채택 여부를 정하고, [실패 조건]은 [대체 흐름]으로 처리한다.
